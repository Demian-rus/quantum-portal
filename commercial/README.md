# TASK034 A — изолированный коммерческий каркас

Это основа контрактов и тестов, **не работающая коммерческая система**. Ни один файл этого каталога не подключён к `party-game/index.html` или `sw.js`. Действующие игра, PWA, каталоги, правила, профили и статистика не изменены. Нет облачных ресурсов, регистрации, платежей, внешних запросов, DNS, публикации, APK или IPA. VK Mini Apps в целевые платформы не входят.

## Граница бесплатного каталога

`contracts/catalog.cjs` адаптирует все версии **публичного** редакционного каталога в CatalogManifest v1: `id`, `version`, `access`, `entitlement`, `delivery`, `minClientVersion`. Все существующие версии и будущие бесплатные G-партии получают `access=free`, `entitlement=null`, `delivery=local-free`. Декларация доступности режима/набора не изменяется: право free не делает исторически отключённый набор играбельным. ID карточек и версий не меняются. На исходном main 67 версий наборов, general@48 — 7 000 заданий; это описание baseline, не ограничение будущего бесплатного объёма.

Будущий платный набор имеет новый стабильный ID, `access=paid`, конкретное право и `delivery=protected-server`. Его реальные данные хранятся **вне публичного репозитория и исходников приложения**, не в `party-game/content`, JavaScript, assets, APK или SW. Тестовый `fictional-moon` содержит только фиктивную строку. Отдельная коммерческая схема не меняет исторический `content/manifest.json`.

## Аккаунт и права

Серверный `acct_*` — учётная запись покупки/подарка, не локальный профиль игрока. Один аккаунт может играть несколькими локальными профилями; их ID, totals, team ledger и backup не используются как пароль или право покупки. Текущая игра ничего не отправляет.

Entitlement v1 включает ID выдачи, accountId, scope, source (`purchased`, `granted`, `owner`), issuedAt, expiresAt, revokedAt и version. Бесплатное право выводится из проверенного каталога как `free`; клиент не может объявить платный набор бесплатным на сервере. Истёкшие/отозванные права закрыты. `owner` — серверный wildcard `*` с expiresAt=null: распространяется на новые дополнения без переиздания APK. Проверка минимальной версии протокола остаётся обязательной. `minClientVersion=1.0.0` — версия будущего API-клиента, не подмена нынешнего номера PWA v98.

`server/service.cjs` получает подтверждённый principal от отдельного auth-адаптера и заново проверяет действующие grants **при каждом запросе материала**. Подписанный Ed25519 snapshot ограничен аккаунтом, ключом и минутой; он нужен будущему UI, не служит bearer-пропуском к контенту. При выдаче проверяется актуальная серверная БД. Подписной ключ существует только в памяти теста; в репозитории нет ключей или секретов. Внешний вход не реализован: default stub возвращает AUTH_NOT_CONFIGURED, а платежный адаптер всегда PAYMENTS_DISABLED.

API контракта: `GET /v1/auth/session`, `GET /v1/entitlements`, `GET /v1/content/{id}/{version}`, заголовок `X-QUIP-Client-Version`. Материал выдаётся только после проверки и записи audit. Ошибка auth/БД/audit/material storage закрывает выдачу, не возвращает фиктивный успех. Ответы no-store, без CORS-разрешения. Неизвестные методы и маршруты не создают аккаунты и не начисляют права.

## Владелец и бессрочные подарки

После реального запуска владелец входит через проверенный auth-провайдер. Администратор вне публичного API связывает подтверждённый auth subject с серверным accountId и вызывает `grantAccess` с source=owner, scope=`*`, expiresAt=null. Нельзя определять владельца по имени локального профиля, IMEI, телефону, user-agent, cookie, localStorage или константе в APK.

Подарок: тот же доверенный серверный admin workflow с source=granted, scope конкретного дополнения, expiresAt=null и уникальным operation/grant ID. `grantOnce` обязан атомарно сохранить grant и audit; повтор операции идемпотентен, конфликт одного ID с другим содержимым — ошибка. Публичного admin endpoint нет. SQL v1 задаёт аккаунты, приобретения, grants и audit, уникальность идентичностей/receipt и связь purchased с подтверждённым приобретением. Реальный transactional DB adapter и админ-инструмент ещё предстоит реализовать. Ручной путь сейчас не создаёт purchased; подтверждение платежа всегда выключено.

До сервера безопасная постоянная авторизация владельца невозможна. `node commercial/debug/preview.cjs` запускает **отдельный loopback** preview фиктивных прав с одноразовым случайным URL; он ничего не разблокирует в игре. Публичная сборка не содержит этот модуль или сгенерированную страницу. Это не готовая debug APK для телефона; мобильная оболочка потребует отдельной сборки/проверки. Скрытого универсального bypass нет.

## Сборки и доставка

`build/public-files.json` — явный список текущих публичных runtime-файлов и бесплатных assets. Сборка читает байты **из точного git SHA**, а не грязного рабочего дерева. Ни весь репозиторий, ни папка assets целиком не копируются. Новые бесплатные ресурсы добавляются в allowlist после review; очередные G-партии продолжают менять прежние сгенерированные бесплатные файлы. Backend, debug, тесты, редакционные источники и будущие private материалы в выпуск не попадают.

```
node commercial/build/build.cjs --sha <40-hex-reviewed-SHA> --variant public-web --out <new-absolute-directory-outside-repo>
node commercial/deploy/plan.cjs --dry-run --sha <40-hex-reviewed-SHA> --out <another-new-absolute-directory>
```

`public-web` — бесплатный web/PWA bundle с прежней игрой, без подключённого сервера. `debug-preview` явно помечает отдельную тестовую цель. `future-android-wrapper` / `future-ios-wrapper` используют тот же web bundle, но **не производят APK/IPA**. Шаблоны wrappers описывают ещё необходимые SDK, app ID, подпись вне git и физические проверки. Дублирования движка нет.

Dry-run создаёт manifest SHA/размеров/SHA256 каждого файла и deployment plan: networkOperations=[], cloudResources=[], releaseEnabled=false. Любая попытка `--execute`, `--host`, `--upload`, `--release` отвергается; транспорта SSH/rsync/cloud SDK нет. Выходной каталог не перезаписывается.

Compose, Caddy, SQL и config.schema/example — будущие Linux VPS/Yandex Cloud шаблоны. Все сервисы требуют явно выбранный future-deployment profile и ещё не заданные image digests/локальные пути. Ничего не запускается и не загружается. Public proxy — только локальный 127.0.0.1:8080; API вынесен на отдельный origin 127.0.0.1:8081, backend/auth инертен, CORS закрыт. CI вызывает только `docker compose config --quiet`, не pull/up/migrate. TLS/DNS и настоящие provider configuration отсутствуют.

`deploy/release.workflow.example.yml` лежит **вне исполняемых GitHub workflows**, job дополнительно if:false. Будущий релиз: проверенный SHA → воспроизводимый public bundle → независимый review → protected environment с ручным одобрением владельца → отдельно реализованный транспорт. Нынешние Pages/release pipeline не меняются. Наличие этого шаблона не даёт разрешения на публикацию.

## Публичная/приватная разработка

Нынешний репозиторий остаётся публичным. Будущие premium payload и серверные секреты — отдельный приватный репозиторий/хранилище с минимальными правами. Work должен быть явно подключён к нужному приватному репозиторию владельцем; публичный build читает только проверенный публичный allowlist и не получает private credential. Перенос открытой истории в private сам по себе не отзывает уже скопированные файлы. Нельзя коммитить настоящие платные материалы даже временно.

Оплаченная офлайн-игра неизбежно доставляет расшифрованный материал устройству: абсолютной защиты от извлечения нет. Будущие варианты — только онлайн-выдача или ограниченная offline-лицензия с компромиссом отзыва/копирования. Сейчас premium не кешируется и не подключён. Шаблон уже разделяет public и API origins: существующий SW не перехватывает запросы другого origin. В реальном релизе потребуются отдельный API hostname/TLS и строго заданный CORS, либо отдельно проверенный network-only маршрут. Cache-Control сам по себе не запрещает явный cache.put внутри SW. Изменение SW сейчас не требуется и не выполняется.

Сборка проверяет замыкание локальных ссылок HTML/CSS и наличие runtime CSS/JS в precache. После одобрения владельцем PR B #188 объединён в main `89a980fce1c6361936b3a96b5b3412beb738a436`. Его бесплатный `responsive-layout.css` явно включён в reviewed allowlist; sourceBase указывает на этот принятый main. Интеграция не меняет ни одного runtime-файла игры и сохраняет отказ при любой другой неразрешённой ссылке, premium/debug/private ресурсе или неполном offline bundle. Новые G-данные в уже включённых runtime-файлах этого изменения не требуют.
