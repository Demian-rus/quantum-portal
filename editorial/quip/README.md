# КВИП: редакторская модель TASK041

Этот каталог содержит **черновую редакцию**, пока не подключённую к игре. Основа — опубликованный TASK039 (`73147f83f1ed23988205468924bac837f1dc4650`, `general@68`). Наличие записи и успешная проверка JSON не означают завершённого смыслового аудита.

Исторические файлы `party-game/content/`, их ID, тексты, старые версии каталогов и сохранения здесь не переписываются. Новая классификация хранится отдельно. В черновике 7 460 активных заданий общего словаря и 237 дополнительных заданий существующих тематических наборов. Дополнительные задания не увеличивают число карточек `general`.

## Модель

* `source.path/fingerprint` связывают решение с точной исторической записью; SHA-256 считается по каноническому JSON, включая непубличные поля числового задания. Сам ответ в редакцию и отчёт не копируется.
* `songLanguagesDigest` закрепляет отдельный снимок проверенного языка песен из TASK039. Он важен для старых песенных ID без `meta.language`: изменение внешнего журнала не должно менять уже опубликованную редакцию.
* `proposal` — неизменяемая миграционная подсказка: прежняя форма, категории general@68, общий старый уровень и существующие пакеты. Это не подтверждённое решение.
* `classification.categories` — о чём задание; допускается несколько категорий.
* `classification.themes` — в каких самостоятельных тематических наборах задание уместно. Тема не заменяет категорию.
* `classification.form` — слово, словосочетание, идиома, песня, персонаж или числовой вопрос. Уточнение word/phrase/idiom не переименовывает исторический ID.
* `classification.modes` — отдельная допустимость и сложность каждого режима. У недопустимого режима сложность `null`. «Секретный» всегда использует сложность фактического способа подачи.
* `review` — статус, автор, время и индивидуальное объяснение решения. `pending` не имеет атрибуции проверки; `needs-source` содержит конкретный нерешённый вопрос; `reviewed` требует полного решения.

Формат описан в [schema-v1.json](schema-v1.json), смысловые правила — в [RUBRIC-v1.md](RUBRIC-v1.md). Исполняемый валидатор дополнительно проверяет актуальность источников, полноту ID и реальные ограничения режимов. JSON Schema сама по себе этого не доказывает.

## Команды

Из корня репозитория, Node.js 22+, без дополнительных зависимостей:

```sh
node editorial/quip/editor.cjs check
node editorial/quip/history.cjs 73147f83f1ed23988205468924bac837f1dc4650
node --test editorial/quip/tests/*.test.cjs
node editorial/quip/editor.cjs audit > /tmp/quip-editorial-audit.json
node editorial/quip/editor.cjs review-batch 0 100 > /tmp/quip-review-batch.json
node editorial/quip/editor.cjs apply /tmp/quip-decisions.json reviewer-name
node editorial/quip/review-table.cjs editorial/quip/reviews/persons-01.psv reviewer-name
node editorial/quip/editor.cjs check --release
```

`review-batch` перемешивает порядок по хешу ID, а не группирует соседние номера. Решение `apply` содержит `id`, точный `fingerprint`, полный `classification` и `rationale`. Все решения сначала валидируются в памяти; ошибка одного не записывает остальные. Не использовать автоматическое присваивание reviewed по диапазону, категории, словарю ключевых слов или старой сложности.

Альтернативный формат `.psv` хранит индивидуальные решения в явных колонках всех режимов, с причиной в каждой ячейке (`medium:concrete`, `-:not-visual`), точным текстом и общим fingerprint источников перечисленных ID. Столбец `ambiguities` разделяется `~`. Парсер не выводит сложности из соседних строк. Файлы в `reviews/` — проверяемый журнал решений; тест сверяет их с редакцией. Автор `codex-semantic-review` означает индивидуальную смысловую работу модели, а не независимую человеческую приёмку.

`audit` показывает неподтверждённые записи, неоднозначности, причины исключения, распределения, пересечения категорий, дубликаты NFKC/ё, подозрения на множественное число и матрицу theme × category × mode × tier. Множественное число — предупреждение для лингвистической проверки: «очки», «ножницы» и «пельмени» нельзя автоматически переделывать. Числовые ответы, вычисления и ссылки с ответами в отчёт не попадают.

`history.cjs` сверяет опубликованные регистрации, саму редакцию и её языковой снимок с базовым Git-коммитом. Удаление контрольной суммы из манифеста не позволяет обойти неизменяемость. CI выполняет эту проверку и валидирует все зарегистрированные версии, а не только текущий черновик.

Минимум общего словаря для Блица — три различных нормализованных задания выбранного уровня; для остальных режимов — одно. Сохраняется более строгий минимум тематического пакета (сейчас пять); одинаковый текст с разными ID не увеличивает доступный пул. Недостаточная комбинация показывается как недоступная, без подмены уровня. Для Секретного строки матрицы показывают объединение подходящих реальных методов; при планировании каждый выбранный метод также должен пройти свою проверку. Сводная матрица не заменяет проверку конкретного плана с историей повторов и языком песен.

## Версии и пополнение

1. Установить источник и проверить лицензию/происхождение новой записи. Создавать новый неизменяемый исходный файл и новые уникальные ID, не менять старый исходник. Добавить его в существующий content pipeline и baseline lock по правилам проекта.
2. Составить новую явную версию каталога, не изменять `general@1–68`. Старые партии продолжают ссылаться на прежнюю версию.
3. Зарегистрировать следующую редакцию с собственными ссылками на каталоги. Скопированное решение можно сохранить лишь при точном совпадении fingerprint и неизменной рубрике; новые/изменённые записи остаются pending до индивидуальной проверки.
4. Проверить форму, нормализованные дубли, все режимы, категории и темы, полисемию, наличие источника и пригодность для широкой аудитории. Сохранить объяснение и автора.
5. Проверить реальные пулы, безопасный лёгкий Draw, фильтры категорий, сохранения и отказ неизвестной версии; затем build/check и обязательную игровую матрицу.
6. До подключения к игре нужна полная проверка `check --release`, отдельная интеграция и приёмка владельцем. Опубликованная редакция получает статус `published` и SHA-256 в `manifest.published`; её нельзя редактировать — только добавлять следующую версию. Публикация редакционного JSON не публикует PWA автоматически.

В TASK041 не входят Быстрая игра и Реванш (TASK040). Черновик не меняет баллы, таймеры, три слова Блица или порядок режимов.

## Контракт подбора перед подключением

`compile.cjs` выдаёт компактные метаданные без текстов и числовых ответов. Он отказывается собирать непроверенную редакцию. `selector.js` проверяет формат, строит пулы по реальным исходным объектам, учитывает типы, темы, исключённые категории и язык песен. Он не выбирает случайную карту, не расходует RNG и не меняет историю. Эти модули пока не загружаются опубликованной игрой.

Политика уровня отдельна от общей сложности правил раунда: исходные значения Draw/Mime — easy; Блиц — все три подходящих уровня; остальные обычные режимы следуют общей сложности. Для Secret исходный выбор «как у способа» использует настройку выпавшего метода. Явный уровень Secret дополнительно ограничивает этот набор; он не превращает настройку лёгкого Draw в hard. Пустое пересечение остаётся пустым. После подключения интерфейс должен объяснять недоступный выбор и фиксировать политику в снимке партии, отдельно от будущих настроек.
