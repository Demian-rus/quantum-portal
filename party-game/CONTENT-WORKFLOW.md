# Контент КВИП: добавление без изменения движка

Редактируемый источник — `content/manifest.json` и перечисленные JSON-файлы. Браузер читает только совместимые с прежним API артефакты `cards.js`, `approx-questions.js`, `content-packs.js`. Они коммитятся вместе с источниками. Ни сервер, ни сборщик приложения, ни дополнительные браузерные запросы не нужны.

## Исторические данные

13 исходных файлов сохраняют 3536 карточек, 150 вопросов и 10 деклараций наборов контрольного main 6c9f428. `baseline-lock.json` фиксирует количество и SHA-256 сериализованных объектов каждого источника. Генерация сохраняет значения, постоянные ID и порядок; отдельная регрессия защищает полные исходные массивы. Старые источники не удалять, не переставлять и не редактировать ради нового выбора. Новые данные — новые ID и отдельный файл. Исторические правила, наборы и текущие снимки партий не пересчитываются.

## Например, добавить 500 слов

1. Создать `content/cards/general-next.json`: массив структурированных записей. У каждой постоянный уникальный ID вида `word-011001`, текст, `type`, `difficulty`, `categories`, `pack`. Проверить свободный диапазон ID; не переиспользовать старые. Пример ID — не автоматический распределитель.
2. Разделить easy/medium/hard редакционно. Проверить естественность, пригодность для доступных способов и смысловые совпадения. Не генерировать массовые сочетания ради объёма.
3. Категории — смысловые теги, возможно несколько; pack — происхождение редакционной партии. Например, научная карточка может иметь science/biology/technology, но source pack остаётся идентификатором её выпуска. Не размечать старые записи по совпадению слова.
4. Добавить источник **в конец** массива cards в manifest: `{"path":"cards/general-next.json","immutable":false,"review":"Что проверено редактором и какие категории подтверждены"}`. Для новых неизвестных категорий добавить id/name в categories того же manifest. Это открытая редакционная таксономия; код app.js не изменяется и новая тема в меню не появляется.
5. `meta` — дополнительные проверочные сведения, скрытые от игрока: музыкальные примеры, происхождение, будущие явные ключи эквивалентности/применимости. Метаданные сами по себе не вводят новую политику выбора; она получает собственную версию на соответствующем этапе.
6. Выполнить команды ниже. Все подозрительно близкие формулировки рассмотреть вручную. Для обычного пополнения не нужны скриншоты, длительные симуляции и повторение полного браузерного CI.

```bash
node party-game/scripts/content.cjs build
node party-game/scripts/content.cjs check
node party-game/scripts/content.cjs audit > /tmp/quip-content-review.json
```

`build` сначала валидирует источники, затем детерминированно создаёт три runtime-файла. `check` ничего не меняет и обнаруживает устаревшие артефакты. `audit` дополнительно выдаёт близкие тексты и редакционные предупреждения; это кандидаты, а не автоматическое доказательство смыслового дубля. Регистр, Unicode NFKC, пробелы, пунктуация и ё/е нормализуются. Общая часть большой фразы не становится автоматически идентичным заданием. 26 старых групп совпадений зафиксированы как точные исторические исключения; новый участник такой группы не получает автоматического разрешения.

## Числовые вопросы

Источники в questions содержат полные объекты id/question/answer/unit/difficulty/categories/note/source/pack. Ответ должен разбираться как конечное число; поддержаны русская десятичная запятая, знак минуса и научная запись. Для эмпирического факта нужна проверенная институциональная HTTPS-ссылка; дата/методика/округление — в вопросе и note. Валидатор проверяет синтаксис ссылки, но не её истинность и актуальность. Формулы проверяются в ограниченном арифметическом контексте. Существующие формулы и определения сохранены исторически; будущий активный выбор «Примерно» будет пересмотрен в TASK 009 E, а не в этом инфраструктурном этапе.

## Например, подготовить Спорт

Создать проверенный тематический контент и добавить новую категорию sport (уже предусмотрена как пример таксономии). Затем создать отдельный `content/packs/sport-v1.json` и добавить путь в packs manifest. Декларация использует прежние поля id/version/name/enabled/categories/types/criteria/minCardsPerPool и при необходимости allowedModes/secretMethods. Source packs и категории фильтруются независимо, без общего fallback. Добавление нового файла декларации не требует изменения app.js.

Регистрировать активную тему только после полноценного наполнения и редакционного контроля. Проверить каждый достижимый метод и каждый уровень: отдельные пулы людей, песен, вопросов, коротких easy-слов Блица и способов Секретки. Технические три слова Блица — не достаточный продуктовый объём. Категория без декларации ничего не включает в меню.

Для расширения Географии или Науки новая декларация получает @3 с явными исходными наборами; geography@2/science@2 остаются неизменными и продолжают фильтровать прежние source packs. Исходные @1 также сохраняются. Аналогично будущие политики активности и эквивалентности вводятся отдельно от правил наград V1–V5.

## Производительность и проверки

`node party-game/scripts/content.cjs stats` выполняет лёгкий локальный замер без браузерного аудита. В одном прогоне Node v24.19: cards.js 455940 байт / 48595 gzip; questions 47272 / 13864; packs 10379 / 3080. Разбор текущего массива и индексов — около 9 мс; синтетического массива 10000 записей с индексом — около 41 мс. Это измерения этой машины, не обещание скорости телефона. Причин вводить сложную динамическую загрузку на данном объёме не обнаружено.

CI всегда проверяет согласованность артефактов и прежние логические/браузерные сценарии. Скриншоты по умолчанию не создаются; для конкретной визуальной диагностики задать `QUIP_SCREENSHOTS=1` или отметить screenshots в ручном запуске workflow. Путь проверки сохранений включает отказ от сброса, подтверждённую резервную копию и офлайн-восстановление. Интерфейс, изображения, правила и награды в этапе A не перерабатываются.

Резервная запись восстановления ограничена одной копией `iskra-party:recovery:v1`; перед её заменой пользователь получает явное предупреждение. Основной ключ и root version:1 прежние. Неизвестная версия не трактуется как повреждение и не сбрасывается через этот путь.
