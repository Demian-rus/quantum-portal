## Поведение и границы

«НОВАЯ ИГРА», стандартный/тематический выбор и внутренние входы `game-type/themes/setup/advanced` направляются в четыре шага «Мастера». В адаптере удалены флаг включения, переключатели, обработчики отключения и процедура возврата контролов в старое оформление. Это удаление маршрута, а не CSS-скрытие кнопок. Старые DOM-контейнеры и контроллеры остаются внутренней реализацией движка: перемещаются настоящие профили, параметры, доступность режимов, RU/EN и START.

Все значения устаревшего query `setup`, включая повторяющиеся параметры, удаляются через replaceState при загрузке и popstate. Остальные параметры, hash и history.state сохраняются. Нет сохранённого предпочтения интерфейса и нет нового ключа данных. Back/Forward не могут восстановить выключенный режим: такого режима в адаптере больше нет.

TASK029 `viewStamp/refreshOptions` сохранены дословно. Доказанный регрессионным сценарием дефект: при отклонении снятия последнего режима контроллер не меняет options, но браузер уже снял checkbox, и кеш не вызывает полный renderer. Обёртка renderOptions после refreshOptions восстанавливает checked из настоящих options.modes. Так же восстанавливается отклонённый недоступный режим. Это только DOM-проекция, без нового сканирования каталогов, записи или изменения правил; Android-тест проверяет состояние, точный RAW и ноль повторных проверок/пулов. Валидация и memo живут в прежних границах; START использует оригинальные контроллеры. 48 остальных JS, style.css, каталоги, правила/RNG/очки, история, профили, хранилища и backup остаются byte-exact относительно базы. Меняется только адаптер и его CSS-шапка, ресурсные версии JS v4/CSS v2, уникальный SW cache `kvip-pwa-v91-20261027-wizard-only-candidate-guard`.

## Проверки

- TASK030 guards сравнивают 48 JS, game CSS, HTML/SW вне точных ресурсных изменений и оптимизацию TASK029 с точной базой.
- TASK030 Android: Pixel 7 UA, isMobile/hasTouch/DPR2.625, 320×568, 390×844, 412×915, 844×390, CPU4. Обычный/старые URL, сохранение других query/hash, все шаги, Back/Forward, reload, themes, rules/RU+EN, START, native SW offline, закрытие и повторный запуск браузера с persistent PWA profile.
- n20 trusted touch для шести прямых/обратных переходов на каждом разрешении в network и offline. Бюджет median≤200 / p95≤350 мс и ноль повторной проверки каталогов на чистых шагах. Сохраняются окружение, PNG, сырые samples, Long Tasks и сводки в `artifacts/quip-task030/mobile.json`.
- Native SW: точный опубликованный TASK029 → TASK030 → точный опубликованный rollback → TASK030, cold offline; точные RAW, профили, заработанная история, paused timer. Исторические v89/v90 и все прежние upgrade fixtures остаются точными git-бандлами.
- Прежние тесты используют явные UI helper-функции для переходов к реальным шагам. Они не подменяют DOM, контроллеры, результаты или состояние. У исторических бандлов без адаптера helper использует их исходные кнопки. Проверки старых gears/двухколоночной формы заменены проверками центра правил/четырёхколоночных плиток, включая прежние источники, nonempty guards и сохранение.
- В browser job `if: !cancelled()` позволяет собрать все строгие ошибки за один прогон. Нет continue-on-error; любая ошибка оставляет job красным. В mobile-layout аналогично собираются все подсценарии и обязательный финальный assert отвергает любой их отказ. Старая диагностическая workflow TASK029 сравнивает wizard/legacy и ограничена её веткой; для TASK030 обязательные CPU4 guards и полная mobile проверка выполняются в основном CI.

Этот тест не входит в опубликованный обязательный workflow. Его исходник и словари не изменяются в TASK030; обязательный список CI сохраняется целиком плюс два новых guards. Не следует называть wildcard полностью зелёным.

Точный проверенный Head, ссылки на оба события CI, фактические измерения и артефакты фиксируются в описании Draft PR #158. Задача готова к независимой проверке только после полного зелёного CI; публикация требует отдельного разрешения.

## Ограничения и откат

Физического Android в Work нет. Chromium mobile emulation/CPU4 не воспроизводит ARM/GPU, thermal, Android launcher и физический input/display pipeline. Предыдущая физическая приёмка TASK029 владельцем не является приёмкой нового TASK030.

Пользовательского переключения на legacy больше нет, включая `?setup=legacy`. Полный откат после отдельно разрешённой будущей публикации: проверенный revert TASK030 к исходному runtime базы, затем новые уникальные cache/resource версии для восстановленного bundle, полный SW update/offline/данные CI и отдельное разрешение на deploy. Не очищать данные сайта, не удалять или мигрировать сохранения. В PR только проверяется roundtrip на точный старый бандл; публикация не выполняется.
