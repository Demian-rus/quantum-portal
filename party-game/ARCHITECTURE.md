# QUIP — архитектурные контракты

## Этап 1: карточки

`cards.js` является авторитетным каталогом 3016 активных заданий. Явный `id` закрепляется за карточкой навсегда и не должен меняться при редактуре текста, переносе между уровнями или наборами. Новый контент получает новый ID; старые ID не используются повторно. `type`: word/phrase/idiom/song/person; `difficulty`: easy/medium/hard; `categories`: набор тематических тегов; `pack`: core/music/people. `meta` используется для проверочных сведений (например, пример песни и артист), которые нельзя показывать отгадывающему.

Пустой массив `categories` означает, что тематическая классификация ещё не проведена. Не следует автоматически присваивать темы по одному слову. `getCardPool` возвращает структурированные записи, а `getPromptPool` временно преобразует их в строки для существующего игрового процесса. Исторические наборы `words.js`, `extra-words.js`, `curated-*.js` остаются в репозитории для аудита и последующей контролируемой миграции; они больше не являются авторитетным источником активного контента.

## Следующие независимые подсистемы (ещё не реализованы)

1. **Ruleset:** неизменяемая версия на партию (`rulesVersion`) с таблицей баллов по режиму/сложности, продолжительностью, условиями завершения и ничьей. Не смешивать с форматом сохранения `version:1` и историческим `scoringVersion`.
2. **Modifiers:** отдельный каталог усложнений с ID, применимыми режимами, тяжестью и собственным версионированием. Усложнение не равно карточке или теме. Нельзя применять неиграбельные ограничения и незаметно менять текущие сохранённые усложнения.
3. **Penalties and risk:** чистая функция расчёта результата, учитывающая успех, риск, награду, ограничение нулём и настраиваемый штраф. Сначала зафиксировать старую семантику (шанс ~20% после второго хода, штраф до 2), затем отдельно обсуждать баланс.
4. **Round planner:** выбирать сложность на пару ходов, балансировать распределение Микса за всю партию и сохранять план после перезагрузки. Выбор темы должен фильтровать карточки, не менять их сложность.
5. **Presets:** шаблоны начальных настроек с ID и версией без дополнительного экрана на первом этапе.

## Обязательная совместимость

Ключ `iskra-party:v1`, корневой `version:1`, поля `game.current.word`, `game.used` и старая история остаются в исходном строковом формате. Не преобразовывать сохранённые раунды в объекты без миграционного адаптера. Старые `scoringVersion!==2` сохраняют прежние правила. Новые изменения правил, штрафов, Микса и хранения требуют отдельных PR с тестами Node.js, Chromium, offline/PWA и загрузкой старых сохранений.
