# КВИП — TASK 016: резервная копия профилей и статистики (ядро)

## Что уже сделано в этой ветке

Модуль `profile-backup.js` — **изолированная библиотека**. Он не подключён в `index.html` и `sw.js`, не изменяет игровой UI, логику начисления, исходные сохранения или генератор случайных чисел. Присутствует в репозитории для тестирования и последующей интеграции Work отдельным PR.

Для экспорта используется **весь** `kvip-player-profiles:v1`:

- `storeId`, `nextSequence`, `settledThrough` — сохранение защиты от повторного зачёта;
- профили, имена, цвета, созданные даты;
- пожизненные агрегаты и статистика по режимам;
- ограниченные `recent` (до 100 последних) и `lastPair`;
- дополнительные будущие/действующие необязательные счётчики тай-брейков.

Текущая партия в `iskra-party:v1`, незаписанные результаты, история всех карточек, игровые настройки и звук **не включены**. Экспорт может содержать только уже зачисленные результаты. UI должен прямо объяснить это.

## Формат файла

```json
{
  "kind": "kvip-profile-backup",
  "version": 1,
  "exportedAt": 1761300000000,
  "sha256": "64 символа SHA-256",
  "payload": {
    "version": 1,
    "storeId": "...",
    "nextSequence": 42,
    "settledThrough": 41,
    "profiles": [],
    "totals": {},
    "recent": [],
    "lastPair": []
  }
}
```

`sha256` — контрольная сумма **точного** `JSON.stringify(payload)`. Проверка выявляет случайное повреждение файла, но **не является электронной подписью**: человек, намеренно изменивший файл, может пересчитать checksum. На HTTPS PWA используется Web Crypto, без внешних запросов.

## API

- `await createProfileBackupText(profileStore)` — экспорт полного валидированного архива в JSON-строку; нет записи в localStorage.
- `await inspectProfileBackupText(fileText, localStorage.getItem(QUIP_PROFILES_KEY))` — **только чтение**, возвращает `relationship`, `summary` и `current`. Внутри проверяет ограничение размера, версию, схему `validateProfileStore` и SHA-256.
- `await restoreProfileBackupText(localStorage, fileText)` — восстановление **только на пустом устройстве без сохранённой партии**; при имеющихся профилях запрещено.
- `await restoreProfileBackupText(localStorage,fileText,{allowReplace:true})` — полная замена существующего архива, только после отдельного явного подтверждения в UI.

Возможные `relationship`: `empty`, `identical`, `different-store`, `older`, `newer`, `diverged`.

Нет «объединить»: из-за агрегатов и удаляемых старых подробных записей 100 последних партий невозможно гарантировать безопасное объединение двух архивов, особенно когда на двух устройствах один `storeId`, но партии расходятся.

## Гарантии восстановления

1. При наличии **любой** `game` в основном сохранении `iskra-party:v1` (даже `results`) или при его повреждении импорт запрещён. Сначала завершить/разрешить эту игру штатным UI, не вмешиваясь в raw.
2. Если текущие профили уже есть, без `allowReplace:true` импорт блокируется; `identical` — no-op.
3. При полной замене прежний байт-в-байт RAW сначала записывается в ограниченный один ключ `kvip-player-profiles:import-recovery:v1` и читается обратно. Если этот защитный ключ уже занят, **перезапись запрещена**; запрещено автоматически затереть старый recovery.
4. Прямо перед записью проверяется, что оба исходных ключа не изменились с начала операции.
5. После `setItem` данные читаются для подтверждения. Если запись не подтверждена, выполняется проверенный rollback прежнего RAW либо удаление неудачного импорта на пустом устройстве.
6. При невозможности доказать rollback возвращается явная ошибка; UI обязан прекратить работу с профилями, не показывая импорт успешным, и предложить ручное восстановление из файла/recovery.
7. Обновлять `profileStore` в памяти только **после** подтверждённого успешного импорта: `restoreProfiles()` или безопасный reload.

Импорт никогда не мутирует существующие `iskra-party:v1`, `iskra-party:recovery:v1`, начисления или игровой RNG.
