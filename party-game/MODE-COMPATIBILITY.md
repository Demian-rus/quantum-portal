# TASK009 G — совместимость режимов с получателем очков

База — PR #37, `375010ac6ab2def00a6f4759ac679622469260ed`. Отдельная политика `mode-compatibility.js` не меняет конфигурации режимов, награды и rulesVersion.

## Контракт

Новая партия фиксирует `modeCompatibilityVersion:1`. Реестр содержит разрешённых получателей для каждого из восьми режимов. Данетки разрешены только для guesser; остальные режимы допускают обоих. Особая ручная схема «Примерно» остаётся в прежней конфигурации и не заменяется обычной дуэльной наградой.

`modeAwardAvailability` используется отображением и обработчиком выбора, проверкой набора, пресетами, стартом и выбором режима партии. Для будущего режима достаточно объявить совместимость в новой версии политики; неизвестный режим не получает неявного разрешения. Исторические конфигурации mode-config@1 и декларации пресетов неизменны.

## Настройки

Карточка Данеток видима для setter, checkbox отключён и показывает «Доступно, когда очки получает отгадывающий». Обработчик не доверяет одному disabled: синтетическое change-событие также не включает несовместимый режим. Прямой вызов newGame повторно проверяет политику до изменения игры, памяти или сохранения.

При переходе guesser → setter удаляются только несовместимые режимы. Пустой массив сохраняется и переживает перезагрузку. Другие режимы автоматически не включаются: показывается просьба выбрать подходящий, старт недоступен. Обратно к guesser возвращается доступность Данеток, но не их выбранное состояние. Пресеты копируются и фильтруются той же политикой; их исторические данные не меняются. Единственный несовместимый режим пресета может дать пустой выбор, который нужно исправить до старта.

Переход между темами сохраняет профили, но не дополняет опустевший выбор режимами. Предпросмотр доступности самой темы может проверять её возможности без записи этих способов в реальные настройки. Типы заданий по-прежнему подстраиваются под содержимое темы.

## Секретка

Источник способов определяется **до** проверки пригодности. Если включены базовые способы Слова/Жесты/Нарисуй/Напой/Данетки, используются только они. Фильтрация не расширяет этот список при ошибке.

Если включённых базовых способов нет, используется явный `soloSecretMethods`: talk, mime, draw, sing, yesno. Из него отбираются способы, совместимые с получателем, allowedModes/secretMethods темы, текущей сложностью, карточками и обязательным условием V2. При setter yesno исключается всегда; темы без песен исключают sing. Короткое пояснение видно в карточке Секретки. Блиц и «Примерно» не становятся базовыми способами.

Для смешанной сложности пригодность проверяется отдельно для easy/medium/hard. У каждого достижимого уровня должен остаться способ. Обязательное условие должно быть применимо к любой карточке, которую может выдать прежний селектор. При отсутствии способов старт блокируется. `v2SecretMethods` для новой политики возвращает этот же список, не выполняя историческое расширение.

При guesser сохранены три исходных условия Данеток V2: v2-question-budget / v2-no-names-search / v2-no-biography. Протокол «да / нет / не знаю», бонусы, штрафы, шанс условий, история и таймеры прежние. Исходные 51 запись каталога V2 не редактировались; изменён только runtime-адаптер.

## Исторические партии и офлайн

Отсутствие modeCompatibilityVersion в **партии** обозначает историческую семантику. При загрузке поле не добавляется, modes/current/methodId/тексты условий/очки/версии наборов не пересчитываются. Прежние setter-Данетки и уже выбранная Секретка продолжают работать. Исторический fallback V2 остаётся только в этой ветке. Настройки будущей партии отдельно получают новую политику.

Неизвестная, строковая или неподдерживаемая версия в партии либо настройках блокирует запись исходного сохранения. Корневые `iskra-party:v1` и version:1 прежние. Новый модуль и обновлённые runtime-ресурсы включены в кэш v44. Скриншоты не требуются и не включены.

## Проверки

14 целевых Node-тестов используют production newGame/selectAwardTo/selectSetupMode/checkContentPack/rollOutcome/restoreSession. Проверяются матрица, presets и обходы, пустой выбор, все три уровня Данеток, явные способы и сольная Секретка, отсутствие расширения при нехватке карточек/условий, сохранения обеих политик, неизвестные версии, награды/таймеры/все четыре исхода «Примерно» и офлайн-ресурсы.

Дополнительный Chromium-сценарий проходит реальные пресеты, выбранные способы Секретки, три условия Данеток, новые и исторические офлайн-снимки и защиту неизвестной версии. Существующий UI-сценарий получателя проверяет disabled/пояснение, синтетический change, пустой выбор/недоступный старт, reload и явный выбор режима на 320 px, телефоне, ПК и низком альбомном экране. Тесты прошлых правил закреплены как исторические; проверка старых тематических пулов TASK008 явно использует отсутствие новой политики. Массовый аудит баланса не перезапускался.

Полный обязательный CI — Node, шесть Chromium-сценариев и Smoke Tests. Статусы для итогового SHA приводятся в зависимом PR G. Слияние PR #31–37 и G не выполняется. Кнопки индивидуальных параметров режимов остаются отдельным будущим UI-этапом.
