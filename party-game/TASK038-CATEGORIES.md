# TASK038 — категории общего словаря

Issue #213. Существующая ветка `feat/quip-task038-dictionary-categories-20261029`; базовый принятый main `126563ccd1c2a9fcbb8e857eb81b422c02a55701`. Работа не публикуется и не объединяется автоматически. PR215 и редакционные ветки не подключены.

На первом шаге Мастера добавлен свернутый список «КАТЕГОРИИ СЛОВАРЯ». В нем только реально наполненные категории активного general-набора, русские названия из manifest, нативные checkbox и «Включить все». general@48 содержит7000 уникальных ID,22 наполненные категории и2840 записей без тематической разметки. videogames пока не наполнена, memes не опубликована: пустые категории не выдаются за доступные. Новые названия генерируются из manifest при обычном content build, без списка категорий в игровом движке.

Политика исключения: карточка с любым выключенным тегом исключается целиком, включая мультитеги. Неразмеченные записи остаются. Это фильтр существующего общего набора; тематические наборы не меняются. Все задания остаются бесплатными. Полнота смысловой классификации не гарантируется: историческая разметка неполна, автоматическая классификация не добавлена.

Счетчик показывает уникальные ID всего выбранного general-набора после фильтра категорий, до ограничений конкретных режимов, сложности, типов, песенных языков и истории. Сумма размеров категорий не используется. Минимальный размер игрового пула, уникальные тексты Блица и допустимые методы Секретки по-прежнему проверяются реальным checkContentPack() перед START.

Предпочтения общие для1×1 и2×2, в отдельном защищенном ключе `kvip:general-categories:v1`: `{version:1,excluded:[стабильные ID]}`. Запись проверяет исходный RAW и результат. Неизвестная версия, лишние поля, повреждение и ошибки чтения блокируют новую стандартную партию и перезапись настроек. Тематическая игра и восстановление старой партии не используют будущие предпочтения. Выбор категорий сам по себе не переписывает duel/team RAW, профили, статистику, историю или RNG.

На настоящем START копия фильтра сохраняется в `game.contentPack.categoryPolicy`. Все существующие пути выдачи уже передают точный contentPack: обычные типы, песни, персонажи, Секретка, Блиц, Примерно, тай-брейк и командная проекция используют один фильтр. Смена будущих предпочтений не меняет снимок текущей партии. Отсутствие политики — прежнее all-on, без нового поля снимка. Неизвестная версия снимка защищает старый RAW через существующие механизмы восстановления. Корень сохранения version1 и схемы профилей/командных транзакций не меняются.

Для установленных неизменяемых каталогов лениво строится индекс по точной версии набора и идентичности cards/questions/registry. Он использует Set для критериев ID/source packs, сохраняет исходный порядок и ссылки записей. Размерные пулы и счетчики переиспользуются; обычные изменения профиля/цвета/навигации не обходят каталог заново. Явные пользовательские/тестовые изменяемые каталоги идут по прежнему uncached пути. START получает исходный полный валидатор, а не кешированное разрешение запуска. При all-on все исторические general-пулы совпадают с опубликованными по длине, порядку и идентичности объектов.

Ресурсы: candidate PWA v105; content-packs20, app68, team-engine3, team-controller12, session-restoration13, menu-navigation11, setup-wizard13/CSS9. Принятый общий style46 с прозрачной tap-подсветкой и responsive-layout2 не изменены. SW lifecycle прежний; HTML и precache согласованы. Новых runtime-файлов и изменений коммерческого allowlist нет.

Точные разрешенные hunks находятся в `diagnostics/task038/reviewed-hunks.json`. Сначала канонизируется только точное сгенерированное соответствие имен текущему manifest, затем обращаются только утвержденные изменения кода. Иное имя без изменения источника, обход валидатора, RNG, focus, SW lifecycle и посторонний CSS остаются видны старым guards. Все карточки/вопросы/декларации наборов и их порядок защищены побайтно.
