# PWA v78 — интеграция TASK 016 + TASK 017

База: main `042a9392a517d5bfacaee6e2ae3caf42ce99c72f` (опубликованная v75).

Сохранены реализации PR #82 `6b68155a2584eda787dc383e60e36c54cbe8b9c5` и PR #86 `cd6b2067acb984a6ea33d71e2f28d4f7ffde863c`. Исходные PR/ветки не изменялись. География/наука #85/#87/#88/#89 не включены; файлы контента и их версии совпадают с main.

## Разрешение конфликтов

- app.js: регистрируются оба независимых UI; исключение для редактирования комментария из TASK 017 сохранено.
- index.html: оба блока настроек и оба диалога с уникальными ID, все четыре модуля, один app.js. Всего **42** runtime-скрипта.
- menu-navigation.js: Back проверяет оба диалога до перехода по сценам; условие выхода из home учитывает оба; настройки обновляют и recovery, и счётчик замечаний.
- style.css: объединены оба набора классов, общий overflow настроек оставлен один раз.
- sw.js: один cache key v78, объединённый precache, версии общих файлов повышены: style 36, menu-navigation 6, app 62. Модули, неизменные относительно исходных PR, сохраняют собственные версии.
- workflow: оба unit suite, оба browser suite, полная история для pinned RNG-сравнения и артефакты обеих задач. Ничего не отключено. Добавлены отдельные интеграционные проверки.
- tests/logic.test.cjs: VM загружает обе пары модулей. В проверках PWA число скриптов повышено с 40 до 42; проверки полного покрытия кэша сохранены.

## Сохранённые контракты

`profile-backup.js`, `profile-backup-view.js`, `player-profiles.js`, `storage-controller.js`, `session-restoration.js` побайтово совпадают с PR #82. `card-reports.js`, `card-reports-view.js`, `round-selection.js`, `round-actions.js`, `round-settlement.js`, `match-views.js` побайтово совпадают с PR #86. Интеграция не меняет алгоритм RNG, режимный баланс, начисления, существующие снимки партий или содержимое истории. Метаданные ID из TASK 017 сохранены без дополнительной переработки.

Профили, report archive и основной игровой RAW не объединяются. Импорт профилей не заменяет журнал замечаний; редактирование/удаление/очистка замечаний не записывают профили и партию. Действуют прежние запрет импорта при текущей game, watermark, recovery, проверенный rollback и постоянная блокировка при неопределённом результате импорта.

## Приёмка

`backup-reports-integration.test.cjs`: взаимная независимость архивов при восстановлении и CRUD, точность recovery, отсутствие RNG и изменений main RAW; byte-exact контроль принятых модулей.

`backup-reports-integration-browser.cjs`: одна сборка, оба экспорта и независимые JSON-форматы; read-only отмена импорта; смена модальных панелей/Back/Escape/восстановление фокуса; импорт профилей с сохранением жалоб; редактирование жалобы без статистических записей; действующий deadline и нулевой RNG при жалобе; точный paused game после offline reload; оба офлайн-экспорта. Размеры 320×568, 390×844, 844×390. Один дополнительный диагностический снимок настроек.

Существующий profile-backup-browser запускает настоящий переход v75 → v78 на стабильном URL service worker, проверяет точный RAW старых профилей, незавершённой партии на паузе и precache 42/42. Остальные исходные unit/browser suites выполняются полностью, включая тай-брейк, Блиц и скрытие карточки. Точные результаты CI на финальном Head указаны в интеграционном PR.

## Границы

Физический Android не проверяется автоматически; Chromium эмулирует мобильные размеры, touch и Back. Web Storage не предоставляет межвкладочный CAS; аварийная блокировка импорта требует ручной проверки, как в TASK 016. Других продуктовых изменений в интеграции нет. Эта ветка остаётся Draft и не объединяется в main исполнителем.
