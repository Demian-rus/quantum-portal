# TASK042B — встроенный словарь

Рабочая ветка `feat/quip-task042b-device-dictionary-20261103`, Draft PR #225.
Зависит от Draft PR #224. Основное приложение и PWA не опубликованы заново.

## Что работает

Настройки → Словарь: последовательное добавление, список, поиск, фильтры по типу,
категории и теме, изменение/удаление, автосохранение черновика, JSON-экспорт и
проверенный атомарный импорт. Поддержаны все шесть форм заданий; несколько
категорий; темы отдельно; независимые уровни семи прямых режимов и наследование
Секретки по фактическому способу. Для числового вопроса обязательны конечный
ответ, единицы, HTTPS-источник и текст проверки. Лимиты: 500 карточек, 240 символов
в тексте, файл до 2 МБ. Word с пробелом отклоняется с просьбой выбрать
словосочетание. Дубли учитывают NFKC, регистр, пробелы и Ё/Е, включая основной
словарь. Некорректный/неизвестный формат не перезаписывается; доступен экспорт
исходного JSON для восстановления.

Переключатель «Использовать мои задания в новых партиях» находится в «Мои задания».
Пользовательский набор дополняет основной словарь и проходит существующие
фильтры игры. Категории/темы и уровни не подменяются. Нет обещания, что новое
задание выпадет немедленно: выбор идёт из общего допустимого пула.

Все функции редактирования, поиска, черновики, JSON и игры работают офлайн.
Каждая новая партия фиксирует точный quip-device@1 снимок и SHA-256. Снимок
входит в существующее сохранение партии, не зависит от текущей версии хранилища,
не меняется при правках/удалении и проверяется при восстановлении. Исторические
партии без снимка продолжают использовать прежний селектор. Опубликованные
каталоги, ID, классификация quip@1 и правила TASK041 не переписаны.

PWA v117 содержит все 61 скрипт и CSS редактора. No-store запросы сессии/квитанций
не попадают в статический кеш. Код защищён точными обратными hunks и отрицательными
проверками, остальные исторические сравнения остаются строгими.

## GitHub: реальное состояние

Карточка сохраняется локально до любой сетевой операции. Очередь содержит
неизменяемый payload и SHA-256 ключ версии, ретраи с задержкой, отдельные статусы
ожидания/отправки/проверки/принятия/ошибки. Онлайн-событие, запуск и периодическая
проверка видимого приложения запускают отправку после настройки сервера. Успех
возможен только по проверенной квитанции API с совпадающим ключом и PR данного
репозитория. Импортированные статусы сервера не считаются доказательством.

**Обмен с настоящим GitHub с телефона не подтверждён: сервер не подключён.**
Поле `meta[name=quip-dictionary-api]` пустое, поэтому интерфейс честно сообщает
об отсутствии сервера и сохраняет очередь. В браузерных файлах нет PAT,
приватного ключа App или пароля. Непроверенные задания в main не отправляются.

Подготовлены `server/quip-dictionary/service.cjs`, исполняемые контрактные тесты
и `server/quip-dictionary/API.md`. Серверный core проверяет владельца
`Demian-rus`, права на репозиторий, Origin и CSRF, идемпотентность; использует
существующий валидатор и компилятор quip@1; пишет только pending intake-документ
в отдельную staging-ветку и Draft PR через обязательный GitHub App адаптер.

Для живой интеграции ещё нужны: HTTPS-сервер; зарегистрированный и установленный
GitHub App с server-only секретами; OAuth callback и HttpOnly-сессии;
production-адаптер GitHub App; долговечный атомарный ledger квитанций; разрешённый
origin PWA и cookie-политика. `API.md` задаёт точные интерфейсы и live-приёмку
(вход владельца, реальный Draft PR, повтор того же ключа без второго PR,
восстановление после офлайна). Развёртывание этих компонентов не выдумано.

## Проверки кандидата

- Chromium: 320×568, 360×640, 390×844, 412×915 — PASS: последовательный ввод,
  несколько категорий, дубли, редактура, поиск, черновики, JSON download/import,
  офлайн-добавление и холодная перезагрузка, отсутствие горизонтального скролла.
- WebKit: те же четыре размера и действия — PASS. Для офлайна используется
  настоящий обрыв loopback-соединения с доказательством неуспешного сетевого
  запроса, как в существующем TASK034. Флаг Playwright setOffline у WebKit
  ломает навигацию и на неизменённом main; он не подменяет проверку PWA.
- Экранная клавиатура проверена фокусом ввода и уменьшенной видимой областью
  Chromium/WebKit. Физический Android не был подключён: нужна ручная приёмка.
- Реальный SW A→B, точное сохранение пользовательского JSON, 61 скрипт из
  офлайн-кеша, редактирование без изменения активной партии/профилей — PASS.
- Реальные 1×1/2×2: пользовательский ID, таймер, подтверждённый RAW; изменение,
  удаление и холодная офлайн-перезагрузка сохраняют исходный снимок — PASS.
- Контракт сервера/клиента: разрешения, CSRF/Origin, настоящий компилятор,
  конкурентный идемпотентный повтор, статусы, неверная квитанция — PASS на
  тестовых адаптерах. Это не успешный обмен с внешним GitHub.
- Финальная локальная матрица: **721/721 PASS, 0 FAIL**, включая все игровые,
  редакторские, исторические и новые серверные тесты. GitHub Actions оставались
  queued; успех внешнего CI заранее не объявляется.

## Как проверить на Android до публикации

Откройте ветку PR #225 в GitHub Codespaces. В терминале в корне репозитория:
`python3 -m http.server 8765 --bind 0.0.0.0`. В Ports откройте 8765 с видимостью
Private. Откройте выданный HTTPS-адрес на телефоне под своим GitHub-аккаунтом,
добавив `/party-game/` к адресу. Дальше: Настройки → Словарь → Добавить;
затем «Мои задания» → включить переключатель → начать новую партию.
Это приватный тест ветки, не публикация основного приложения. File:// и обычный
HTTP по IP не подходят для проверки всех возможностей PWA/хранилища.
