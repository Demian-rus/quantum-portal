## Подтверждённая причина tap highlight

Диагностический [прогон исходного интерфейса](https://github.com/Demian-rus/quantum-portal/actions/runs/40553923993) исполняет точные байты production `47a7266…`, извлечённые через `git archive`. Код probe находится в коммите `7fd61c9…`. Эти три версии различаются в индексе доказательств.

При 390×844 область `label` — **173×74 px**, видимый `span` — **112,77×54 px**. Computed `-webkit-tap-highlight-color` исходного label/span/input — `rgba(51,181,229,0.4)`. Реальные CDP touchStart / hold / touchEnd показывают внешнюю подсветку после отпускания.

В области label вне span (с запасом 3 px на обводку) проверяется 5 001 пиксель:

| Вариант | Изменившиеся внешние пиксели в переходном кадре |
| --- | ---: |
| Опубликованное оформление | 5 001 |
| Только прозрачный tap highlight label | 0 |
| Яркий красный положительный контроль | 5 001 |

Последующий settled-кадр исходной версии уже не содержит вспышки. Поэтому вывод основан на промежуточных кадрах и положительном контроле, а не на обычном скриншоте после нажатия. Сырые `tap-probe.json`, held/released PNG и красный контроль находятся в [артефакте диагностики](https://github.com/Demian-rus/quantum-portal/actions/runs/40553923993/artifacts/12756088196).

## Исправление и фокус

Только `.setup-wizard .finish-choices label` получает прозрачный tap highlight. Нативные radio, их click/change, checked-состояние, параметры очков/ходов и обработчики сохранения сохранены.

При pointerdown класс представления меняет фон **только видимого span**. Он снимается при pointerup, pointercancel и blur. Применяется фон, не `filter`: дополнительный stacking context мешал бы прямому hit testing скрытого radio. Существующий `input:checked + span` даёт выбранное состояние, а `:focus-visible` сохраняет видимую клавиатурную обводку. Глобального отключения фокуса нет.

Для `9ce2192…` сохранены **240 кадров удержания/отпускания + 247 кадров сессий быстрого чередования = 487 PNG**. Во всех сравниваемых внешних областях — 0 изменений. Каждая из четырёх геометрий проверена в 1 НА 1 и 2 НА 2, включая 6 покадровых нажатий, 12 быстрых попеременных касаний, доверенные pointerType=touch события, ArrowRight и видимый focus. Непрерывный screencast содержит временные отметки и фазу касания.

## Структура восьми режимов

У каждой секции: иконка и название → текущий статус и награда → нативные `details/summary «Правила»` → отдельные действующие настройки.

| ID | Название | Награда из текущего rulesGuidePage | Настройки вне details |
| --- | --- | --- | --- |
| talk | Слова | +1 | Включение/выключение |
| mime | Жесты | +1 | Включение/выключение |
| draw | Нарисуй | +1 | Включение/выключение |
| sing | Напой | +1 | Включение/выключение, русские/иностранные источники |
| yesno | Данетки | +2 | Включение/выключение с прежним ограничением получателя очков |
| secret | Секретка | +2 базовых + обязательный бонус +1 | Включение/выключение |
| blitz | Блиц | +2 за полный результат | Включение/выключение |
| approx | Примерно | +1 | Включение/выключение |

Пример «Напой +2» не переносился в расчёт: действующая базовая награда +1. Тексты всех блоков, включая «Время», получаются из `rulesGuidePage`, не из независимой копии правил. Текущее время дополнительно выводится из прежних duration/durationBonus. Для 2 НА 2 остаётся прежняя замена обращений к сопернику на обращения к партнёру.

`#mode-toggles` перемещается между сеткой шага 3 и центром. Checkbox остаются единственным набором с прежним делегированным обработчиком; независимого состояния центра нет. Сохранены последний режим, недоступные темы, последний источник, синхронизация обратно с шагом 3, Back/Escape, фокус и локальная прокрутка. При новом входе все восемь details закрыты. Enter/Space открывают и закрывают справку; это не меняет options/RAW и не запускает новую проверку каталога.

Источники «Напой» расположены вне details. Для предупреждения и статуса используется результат настоящего `checkContentPack`, поскольку разрешённость checkbox сама по себе не доказывает наличие песен. Снимок привязан к настройкам и ссылкам на каталоги, конфигурацию и валидатор; история packPreferences исключена, как в TASK029. Первый вход после изменения вычисляет доступность, чистая навигация повторно не сканирует каталог. Вызов существующего контроллера без флага чтения снимка по-прежнему проверяет доступность заново; START не использует этот UI-кэш.

Проверен реальный случай иностранного источника на лёгкой сложности: нет заданий, видны предупреждение и статус, запрос «Напой» блокирует START. Добавление русского источника восстанавливает доступность. Нативные ограничения checkbox не переписаны.

## Ограничения и безопасный откат

- Физический Android не тестировался; выполнена эмуляция trusted touch. Захват дискретен, но положительный контроль доказывает видимость исходной короткой вспышки.
- Источники/доступность кэшируются только в представлении; реальные изменения и START валидируются прежними контроллерами.
- Сохранение черновика 2 НА 2 только при START — сохранённое ограничение, не новая гарантия долговечности незапущенной партии.
- Actions artifacts имеют срок хранения. Сохранённый комплект и хеши фиксируют свидетельства 9ce2192…; новые свидетельства принадлежат своему Head.

Пока публикации нет, откат означает отклонение/закрытие Draft PR без изменений main. После отдельного разрешения на выпуск возможен откат пяти production-файлов на согласованный проверенный комплект в новой обычной ветке, с новым уникальным SW cache name и полным CI. Нельзя очищать localStorage/IndexedDB, удалять team receipts, менять схемы или принудительно переписывать main. Реальный цикл rollback/upgrade уже проверен тестами сохранений; эта процедура сама по себе не является разрешением на публикацию.
